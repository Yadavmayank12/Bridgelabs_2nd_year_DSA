Sorting Algorithms Complexity Analysis – Solution

(a) Big-O Worst Case Proof

Definition of Big-O: A function f(n) is O(g(n)) if there exist constants
c > 0 and n0 ≥ 0 such that f(n) ≤ c*g(n) for all n ≥ n0

Proof for Bubble Sort Worst Case

Worst case operations: T(n) = n^2 - n

Since n^2 - n ≤ n^2

Let g(n) = n^2

Choose constants: c = 1 n0 = 1

For all n ≥ 1: n^2 - n ≤ 1 * n^2

Therefore: T(n) = O(n^2)

Proof for Insertion Sort Worst Case

Worst case comparisons: T(n) = n(n-1)/2

Expand: T(n) = (n^2 - n)/2

Compare with g(n) = n^2

(n^2 - n)/2 ≤ n^2/2

Choose: c = 1/2 n0 = 1

Thus: T(n) ≤ c*n^2

Therefore: T(n) = O(n^2)

Merge Sort Worst Case

Recurrence relation: T(n) = 2T(n/2) + n

Using Master Theorem:

T(n) = Θ(n log n)

Quick Sort Worst Case

Worst case occurs when pivot divides array poorly.

Recurrence:

T(n) = T(n-1) + n

Solution:

T(n) = O(n^2)

(b) Matching Algorithms to Data Types

Type A: Nearly Sorted Data (90% sorted)

Best Algorithm: Insertion Sort

Reason: Insertion Sort best case = O(n) Very few shifts are needed for
nearly sorted data.

Type B: Completely Random Data

Best Algorithm: Quick Sort

Average case complexity:

O(n log n)

Quick Sort is usually faster in practice because it has low overhead.

Type C: Reverse Sorted Data

Best Algorithm: Merge Sort

Reason:

Insertion Sort → O(n^2) Bubble Sort → O(n^2) Quick Sort may degrade to
O(n^2)

Merge Sort always remains:

Θ(n log n)

Final Matching:

Nearly Sorted → Insertion Sort Random Data → Quick Sort Reverse Sorted →
Merge Sort

(c) Difference between Θ(n log n) and O(n log n)

Merge Sort:

Always performs the same operations regardless of input order.

Therefore:

Best Case = Average Case = Worst Case

Θ(n log n)

Theta notation represents a tight bound.

Quick Sort:

Average Case = O(n log n) Worst Case = O(n^2)

Since worst case is worse than n log n, we cannot guarantee Θ(n log n).

Thus we describe average complexity using O(n log n).

Difference:

Big-O → Upper bound

Theta → Exact bound

(d) Algorithm Decision Strategy

Data Size Categories:

Small: n < 50 Medium: 50 ≤ n < 10,000 Large: n ≥ 10,000

Decision Rules:

If n < 50: Use Insertion Sort

Reason: Simple and efficient for small datasets

If 50 ≤ n < 10,000:

Nearly Sorted → Insertion Sort Random Data → Quick Sort Reverse Data →
Merge Sort

If n ≥ 10,000:

Nearly Sorted → Quick Sort Random Data → Quick Sort Reverse Data → Merge
Sort

(e) Mystery Sort vs Merge Sort

Mystery Sort:

T(n) = 5n^2 + 100n + 1000

Merge Sort:

T(n) = 10n log2(n)

We solve:

5n^2 + 100n + 1000 < 10n log2(n)

For large n:

5n^2 dominates 10n log n grows much slower

Compare dominant terms:

5n^2 < 10n log n

Divide by n:

5n < 10 log n

n < 2 log n

This inequality only holds for very small values of n.

Testing example values:

n = 5

Mystery: 5(25)+500+1000 = 1625

Merge: 105log2(5) ≈ 116

Merge Sort faster.

Conclusion:

Mystery Sort grows as n^2 Merge Sort grows as n log n

Thus Merge Sort becomes faster as n increases.

Final Recommendation:

Small datasets → Insertion Sort Random large datasets → Quick Sort
Worst-case guaranteed performance → Merge Sort
